# Задача 8: Склад товаров

**Студент:** Григоренко Даниел Владимирович

## Постановка задачи

Товар описывается: **артикул** (уникальный идентификатор), **название**, **количество** на складе.

Требуемые операции:
1. **Приход** — увеличить количество товара. Если товара с таким артикулом нет — добавить новый.
2. **Расход** — уменьшить количество. Нельзя уходить в минус: если товара не хватает — операция отклоняется.
3. **Остаток по артикулу** — узнать количество конкретного товара.
4. **Товары с остатком ниже порога** — список товаров, у которых количество меньше заданного значения.
5. **Общий объём единиц на складе** — суммарное количество всех товаров.

## Сравнение подходов

### Структурная версия
- **Данные** (`record Product`) и **логика** (статические методы) разделены.
- Все операции — статические методы, принимающие `Map<String, Product>`.
- Проверка «не уходить в минус» живёт в функции `issue`.
- Так как `Product` — неизменяемый `record`, изменение количества делается заменой объекта в `Map`.

### ООП-версия
- Класс `Product` инкапсулирует данные и логику изменения своего количества (`increase` / `decrease`).
- Класс `Warehouse` управляет коллекцией товаров и делегирует изменение количества самому товару.
- Состояние закрыто (`private`), доступ — через методы.
- Проверка «не уходить в минус» живёт в `Product.decrease`.

Обе версии решают одну задачу и дают идентичный результат на одном и том же демонстрационном сценарии.

## Демонстрационный сценарий

Обе программы выполняют один и тот же сценарий:
1. Приход трёх товаров (Молоко — 10, Хлеб — 5, Сыр — 3).
2. Повторный приход молока (+5) — проверка увеличения.
3. Попытка расхода больше, чем есть (Молоко — 20) — отказ.
4. Успешный расход (Молоко — 7).
5. Расход несуществующего товара — отказ.
6. Остаток по артикулу.
7. Товары ниже порога 5.
8. Общий объём единиц на складе.
9. Полное состояние склада.
